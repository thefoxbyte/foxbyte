FoxByte · architecture question

Do we have a storage engine?

15 September 2026 · checked against main @ 2bc87ff · companion to FOX_Checklist.pdf and FOX_Feature_Implemented.pdf
No — by design

FoxByte has no storage engine of its own. Rows, indexes and the write-ahead log are stored by PostgreSQL 18's own engine on local disk. What FoxByte built is a storage layer around Postgres: instant copy-on-write branches, space management, and durability to object storage.

Why no custom engine

The decision

  • Transaction speed must never be compromised — it was the project's first locked requirement.
  • Engines that separate compute from storage put a network hop under every page read and every commit.
  • Stock Postgres on local disk keeps native latency; branching, backups and time travel are handled beside the commit path (copy-on-write file system, asynchronous WAL archiving).

What it means in practice

  • Full PostgreSQL compatibility: drivers, ORMs and tools work unchanged, and extensions can be added to the image (pgvector isn't included yet).
  • Nothing to maintain below Postgres — upgrades follow upstream.
  • Limit: compute and storage run on one host. Scaling storage beyond a machine, or moving a branch between hosts, would need the networked storage that isn't built.
